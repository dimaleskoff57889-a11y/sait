Рабочий документ проекта `~/Desktop/LIFT-SITE`. Здесь собирается всё, что известно о сайте: что это, какие решения приняты, анкета для папы с ответами и что осталось сделать до запуска.

**Как работать с файлом (для других сессий):**

1. Ответы папы вписываются в раздел «Анкета» — под нужным вопросом, в строку «Ответ».

## Что за сайт

| Поле | Значение |
|------|----------|
| Для кого | Папа — мастер по лифтам и подъёмному оборудованию, Москва |
| Статус заказчика | ИП (по текущим данным, подтвердить — см. «Чего не хватает») |
| Формат | Одна страница + отдельная страница политики `/privacy` |
| Кто читает | Заказчики B2B: управляющие компании, подрядчики, владельцы объектов. Сайт рассылается прямой ссылкой |
| Цель | Показать, что мастер реальный и опытный (объекты, допуски, стаж), и дать связаться в один клик |
| Стаж | 20+ лет (подтверждено сыном) |
| География | Москва; область и регионы — по договорённости |

### Блоки страницы (порядок)

Черновик-баннер → шапка → **Hero** (заголовок, подзаголовок, кнопки связи, фото) → **Цифры** → **Услуги** и типы оборудования → **Объекты** → **О мастере** → **Документы** → **Условия** (гарантия, цены) → **Контакты** → подвал (реквизиты, ссылка на политику, «не является публичной офертой»).

Порядок выбран под то, как заказчик читает визитку подрядчика: кто ты и как связаться → что делаешь → чем докажешь → кто ты как человек → допуски → условия → связаться ещё раз.

### Техника

- Next.js 16 (статический экспорт), React 19, Tailwind 4, шрифт Golos Text.
- `npm run dev` — локально на `http://localhost:3000`; `npm run build` — готовая статика в `out/`, Node на сервере не нужен.
- Весь текст и данные — **только** в `src/content/site.ts`. Фото — `public/photos/`, сканы документов — `public/docs/`.
- Палитра в `src/app/globals.css`: серо-синий `steel` + сигнальный `signal`. Когда придёт фото спецовки — подобрать `steel-700/800/900` под её цвет.

## Хостинг: Timeweb Cloud Apps

Сайт — чистая статика (`npm run build` → папка `out/`), поэтому подходит самый дешёвый вариант: **App Platform → Frontend**. Timeweb сам забирает код из GitHub, собирает его и отдаёт файлы. Docker и сервер настраивать не нужно, после каждого `git push` сайт пересобирается автоматически.

- Цена: 99 ₽/мес (1 ГБ NVMe, до 200 000 запросов) — по данным блога Timeweb на 29.09.2026, сверить в панели.
- Репозиторий: `github.com/dimaleskoff57889-a11y/sait`, ветка `master`. ⚠️ **Сейчас он публичный.** Сделать приватным до того, как туда попадут реквизиты, телефон и сканы документов (GitHub → Settings → Danger Zone → Change visibility). Timeweb через подключение GitHub работает и с приватными репозиториями.

### Настройки приложения

| Поле в панели | Значение |
|---------------|----------|
| Тип | Frontend |
| Фреймворк | Next.js, **без SSR** (сайт экспортируется в статику) |
| Регион | Москва |
| Репозиторий / ветка | `sait` / `master` |
| Версия Node | 20 или новее (Next.js 16 на Node 18 не соберётся) |
| Команда сборки | `npm run build` |
| Директория сборки | `out` |
| Переменные окружения | не нужны |
| Автодеплой | включён |

### Порядок

1. Сделать репозиторий приватным.
2. Timeweb Cloud → App Platform → «Создать» → Frontend → подключить GitHub и выбрать `sait`.
3. Заполнить настройки по таблице и запустить деплой.
4. Открыть технический домен, который выдаст Timeweb, и проверить `/` и `/privacy/`. Пока `draft: true`, сайт закрыт от поисковиков и помечен полосой «черновик» — эту ссылку можно спокойно отправить папе посмотреть.
5. Купить домен (`.ru` на данные ИП) и привязать его в настройках приложения; SSL Timeweb выпускает сам.
6. Проверить на домене: открывается по `https`, `www` и без `www` ведут на один адрес.
